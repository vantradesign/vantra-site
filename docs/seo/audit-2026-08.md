# Technical SEO & AI-crawler audit — vantra-site

**Date:** 2026-08-13
**Scope:** `vantra-site` (Nuxt 3, prerendered via `nuxt generate`, Cloudflare Pages)
**Baseline commit state:** before the SEO/GEO engagement
**Verification:** `pnpm run generate && pnpm run verify:seo` — 23 pages, 0 failures

---

## Summary

The site was in unusually good shape on the things that are expensive to fix and
unusually bad shape on the things that are cheap to fix.

Everything structural was already right: `ssr: true` with full prerendering, so
every page ships complete HTML; self-hosted fonts with metric-matched fallbacks;
no third-party scripts; no analytics; no client-side-only content; no login wall;
no accordion or tab hiding text from crawlers; a hard-cached asset layer. There
was nothing to fix in the rendering or performance foundation.

What was missing was the entire discovery and interpretation layer. No
`robots.txt`, no sitemap, no canonical tags, no Open Graph, and no structured data
on any of the 20 routes. The site was crawlable by accident rather than by
instruction, and an answer engine reading a tool page had no way to know who
published it or what it was part of.

**19 issues found. 16 fixed, 3 deferred with an owner.**

## Notable judgment calls

Three decisions where the obvious action was not the right one.

**AI crawlers are allowed, deliberately.** `robots.txt` does not block `GPTBot`,
`Google-Extended`, `PerplexityBot` or `ClaudeBot`. For a site whose tools are open
source and whose goal is citation, being summarised is the distribution channel.
One point worth knowing before anyone revisits this: `Google-Extended` is not a
crawl control at all — it is a Gemini and AI-Overviews grounding opt-out.
Disallowing it would remove the site from AI Overviews while leaving classic
ranking untouched, which is the exact opposite of the objective.

**No `lastmod` in the sitemap.** The available value would be build time, which
would claim every page changed on every deploy. Google distrusts the whole element
when it is unreliable, so omitting it is worth more than filling it. Reinstate it
when there is a real per-page content date.

**The aspect-ratio page gets no reference table.** It already renders the full
eight-row ratio table from `ASPECT_REFERENCE`. Adding the reference layer's own
table would have put the same rows on one URL twice — duplicate content, and two
copies for a model to disagree about. The rule is recorded in
`data/tool-reference.ts`: add a table only where the page has none.

## Honest scope boundary

Everything above is on-site engineering, and on-site engineering is the smaller
half of this problem. It makes the site eligible to rank and mechanically easy to
cite. It does not make anyone link to it, and roughly the large majority of AI
brand mentions originate from third-party sources rather than from a brand's own
domain — Reddit threads, GitHub, comparison posts, community answers.

A site with perfect technical SEO and no external citations will not win
competitive queries like `clamp font generator`, where the incumbents rank on
years of accumulated links. See `docs/seo/offsite-backlog.md` for the work that
actually moves those queries, and `docs/seo/monitoring-runbook.md` for how to tell
whether any of it is working.
